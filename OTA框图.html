三、程序运行中「跳哪个扇区」的不同情况

跳转目标只由 扇区 62（0x7C000）的 magic 和 两个槽的可用性判定 决定；APP 自己不会改跳转槽，只有 Bootloader 会写。
情况 1 ｜ 正常上电（无任何指令，无升级请求）
读扇区 620x7C000
→
magic 判定0x5A5A5A5A / 0xA5A5A5A5
→
检查该槽可用故障计数 < 3 且 SP/复位向量合法
→
跳 APP1 (0x1A000)或跳 APP2 (0x44000)
扇区 62 是擦除态（0xFFFFFFFF）时默认按 APP1 处理，并回写 0x5A5A5A5A。
情况 2 ｜ 正常工况 OTA（APP1 正在运行，升级到 APP1）

→
复位后跳 APP1新的 APP1 (0x1A000)
情况 3 ｜ 正常工况 OTA（当前跑 APP1，把新固件烧到 APP2）
APP1 运行中0x1A000

情况 6 ｜ TBOX 直接指定启动哪个槽（0x01 / 0x02）
下发指令目标槽状态回帧 0x18EF5858动作
0x18FF5858 = 0x01 APP1 可用，且当前槽 ≠ APP1 0x01 扇区 62 写 0x5A5A5A5A → 等发送完 → 复位 → 跳 APP1 (0x1A000)
0x18FF5858 = 0x02 APP2 可用，且当前槽 ≠ APP2 0x02 扇区 62 写 0xA5A5A5A5 → 等发送完 → 复位 → 跳 APP2 (0x44000)
0x18FF5858 = 0x01 / 0x02 当前已在目标槽 0x01 / 0x02 只回帧、不复位（幂等保护，防止 TBOX 连续发指令造成复位死循环）
0x18FF5858 = 0x01 / 0x02 目标槽坏块（故障计数 ≥ 3） 0x04 拒绝跳转，不修改跳转槽，继续按原槽启动
0x18FF5858 = 0x01 / 0x02 两个槽都不可用 0x03 进编程模式等待刷写（同情况 5）

「坏块」判定用到的两个扇区
位置判据说明
扇区 11 / 12
0x16000 / 0x18000		 faultCount < 3 RMU 只把 SWDT / WDT / MPU 错误 算故障；掉电、上电、软件复位不累加、不写 Flash（保护擦写寿命）。升级成功后会整槽清零。
APP1 / APP2 起始地址 SP + 复位向量合法 *(u32*)addr（初始 SP）必须落在 RAM 内；*(u32*)(addr+4)（复位向量）不能是 0xFFFFFFFF 且必须落在 0x1A000–0x6E000 之间。
注意：没有镜像头、没有 CRC、没有签名校验。
一句话总结：APP 只负责「收指令 + 写共享区 + 复位」，Bootloader 负责「判复位原因 + 判指令 + 选槽 + 跳转」， 两者之间唯一的通道是扇区 8（共享状态）和扇区 62（跳转槽）。
